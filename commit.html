Manual runbook · Module 0 + M1 + M2

Five checks before you commit.

Claude Code wrote the bootstrap, the notebook parser, and the bare HTML renderer. It never runs git commit itself. This is the exact sequence you run by hand to land the change.

The whole idea in one line

Claude Code prepared the change and stopped there. Only your own hands ever run git commit, so nothing enters history until a human has looked at the diff.

Ground rule

Why you're doing this by hand

CLAUDE.md is explicit: Claude Code never commits or pushes in this project.

Every step below exists to catch a mistake before it becomes permanent: an untracked file that should have been reviewed, a leaked secret, a test that quietly broke. Run them in order. Each one depends on the one before it.

The sequence

Five steps, in order

Skipping ahead defeats the point: each check exists to catch what the previous one couldn't.

Review what's changing

Look at the staged diff before anything is locked in.

git status --short
git diff --cached --stat

Expected staged (A/M): .gitignore, .env.example, commit.md, pyproject.toml, requirements.txt, notebook_report/ (all files), tests/ (all files), PROGRESS.md, STATE.md.

Stop if you see this

.env should not appear anywhere in the output — it's gitignored. If it does, stop and fix .gitignore before committing anything.

You, before anything else

Confirm everything is already staged

Every line of status should read cleanly as staged, not floating.

git status --short

Every line should read A or M. If anything shows ?? (untracked), stage it explicitly:

git add <path>

Avoid git add -A / git add . — staging explicitly is what keeps .env out even if .gitignore has a typo.

You, one file at a time

Run the tests one more time

The last chance to catch a regression before it's on record.

.venv/bin/python -m pytest -q

Expect: 3 passed.

The test suite

Commit

One commit, three modules, a message that says what actually shipped.

git commit -m "Module 0 + M1 + M2: bootstrap, notebook parser, bare HTML renderer

Module 0 (Bootstrap):
- notebook_report/ package tree with stub modules per PLAN.md
- venv on Python 3.11.11 (via uv), deps installed, requirements.txt frozen
- pytest passing, notebook-report CLI entrypoint runs
- live Anthropic API smoke call confirms key auth (account needs credits)

Module: Notebook Parser (M1):
- notebook_report/parser.py: Cell dataclass + parse_notebook(path), reads
  via nbformat, strips empty/whitespace-only cells, orders executed cells
  by execution_count (unexecuted cells trail in original order)
- tests/test_parser.py + tests/fixtures/out_of_order.ipynb: acceptance
  test against a fixture with out-of-order execution_counts and one
  whitespace-only cell

Module: Report Renderer bare (M2):
- notebook_report/render.py + templates/report.html.jinja: renders an
  ordered Cell list to HTML, one section per cell with source and (if
  present) extracted output text
- cli.py: render command now works end-to-end (parses, renders, writes
  report.html); analyze remains a stub
- tests/test_render.py: asserts source/output appear in correct
  execution order for every non-empty cell"
You, and only you

Verify

Confirm the commit landed and nothing was left behind.

git log -1 --oneline
git status --short

git status --short should now be empty (or show only files you intentionally left uncommitted).

You, closing the loop
