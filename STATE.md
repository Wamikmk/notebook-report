M5: `notebook_report/classifier.py` adds `classify_cells(cells, client=None) -> list[Cell]` and `classify_cell(cell, client) -> Cell`. Uses Anthropic tool-forced structured output (`tool_choice={"type": "tool", "name": "classify_cell"}`) with a hand-written JSON tool schema (label enum + gloss string), not `model_json_schema()` — kept the schema and the `CellClassification` Pydantic model as two small hand-authored pieces rather than deriving one from the other, simplest thing that passes acceptance. Every model response is validated via `CellClassification.model_validate(tool_use.input)` before any field is read (never branches on unvalidated JSON, per CLAUDE.md); on `ValidationError` or a malformed/missing tool-use block, retries once (`MAX_ATTEMPTS = 2` total attempts), then falls back to `proposed_label="UNCLASSIFIED"`, `proposed_gloss=None`. `Cell` gained `proposed_label: str | None = None` and `proposed_gloss: str | None = None` (defaulted, so M1-M4 construction sites and tests are untouched). Reuses `render.py`'s `_output_text` to build the cell's prompt context rather than duplicating output-extraction logic. `client` is an injected dependency (defaults to `anthropic.Anthropic()`, which reads `ANTHROPIC_API_KEY` from the environment itself — classifier.py never opens or parses `.env`), so the acceptance test passes a fake client with canned tool-use responses instead of hitting the network. No new dependency: `anthropic` and `pydantic` were already in `pyproject.toml`/`requirements.txt` from Module 0. `cli.py`'s `analyze` command is untouched (still `NotImplementedError`) — wiring the classifier into the CLI is Module: Review Artifact (M6), not this module.

M1: `notebook_report/parser.py` defines a `Cell` dataclass (id, source, cell_type, outputs, execution_count, stale, reason) and `parse_notebook(path) -> list[Cell]`, which reads via `nbformat.read(path, as_version=4)`, strips cells whose source is empty/whitespace-only, and sorts by `(execution_count is None, execution_count, original_index)` — executed cells ordered by execution_count, unexecuted/markdown cells pushed to the end in original relative order (not itself acceptance-tested; see Decisions).

M2: `notebook_report/render.py` adds `render_report(cells) -> str`, a Jinja2 `Environment` (autoescape on) loading `templates/report.html.jinja`, with a custom `output_text` filter that extracts display text from a cell's `outputs` list (stream text, `data["text/plain"]`, or error traceback, in that priority order). The template emits one `<section class="cell">` per cell with a `<pre class="source">` and, only if output text is non-empty, a `<pre class="output">`. `cli.py`'s `render` command now works end-to-end: parses the notebook, renders, writes `report.html` to cwd. `analyze` is still a stub. The `render` command's Click argument was renamed from `review_path` to `notebook_path` — it takes the `.ipynb` directly for now since Module: Review Artifact (M6, which introduces `review.yaml` and the analyze/render split) hasn't been built yet; expect this argument to change again at M6.

M3: `notebook_report/staleness.py` adds `annotate_staleness(cells, cache_path) -> list[Cell]`. Cache is a flat JSON dict `{cell_id: sha256(normalized_source)}` at a caller-supplied path, loaded if present, rewritten (all current hashes) on every call. Per cell: no prior hash → not stale (first-sight baseline); hash differs from cached → `stale=True`, `reason` set; hash matches → not stale. `Cell` gained `stale: bool = False` and `reason: str | None = None` fields (defaulted, so M1's Cell construction sites and test are untouched). Resolves the CONTEXT.md open question: source is normalized (`re.sub(r"\s+", " ", source).strip()`) before hashing, so whitespace-only edits are never flagged stale — see Decisions.

Reason: uv already had 3.11.11 installed locally from prior use; no system/apt package install needed, so this doesn't trip the "new dependency needs approval" rule. SETTLED.
- [2026-07-24] `parse_notebook` sorts cells without an `execution_count` (markdown cells, or code cells never run) to the end of the list, in their original relative order, rather than interleaving them by position. Reason: PLAN.md's acceptance test only specifies ordering for executed code cells; this is the simplest rule that doesn't require guessing where an unexecuted cell "belongs" relative to executed ones. Not acceptance-tested (fixture is all-code-cells) — revisit if a later module's fixture shows this is wrong for markdown-heavy notebooks. SETTLED for M1.
- [2026-07-24] "Truly empty" cell = `source.strip() == ""` (whitespace-only or zero-length), independent of `execution_count`. Reason: matches PLAN.md's fixture description ("one truly empty cell") and CONTEXT.md's open question about whitespace-only edits not counting as stale (M3 concern) — kept the empty-cell-stripping rule in M1 orthogonal to that. SETTLED for M1.
- [2026-07-24] M2's `render` CLI command takes the notebook path directly (`notebook-report render fixture.ipynb`), not a `review.yaml` — the Click argument was renamed from the module-0 stub's `review_path` to `notebook_path`. Reason: PLAN.md's own acceptance test for this module calls it that way; the review.yaml split is a later module (M6, Review Artifact). Expect another rename at M6. SETTLED for M2.
- [2026-07-24] Output text extraction priority in `render.py`'s `_output_text`: stream `text` first, then `data["text/plain"]` (execute_result/display_data), then `traceback` (error), first match wins per output entry, joined with newlines across multiple outputs. Reason: simplest deterministic precedence that covers the three common nbformat output_types without needing to branch on `output_type` explicitly. Not stress-tested against rich outputs (images, HTML tables) — those fall through to nothing shown, acceptable for the bare renderer. SETTLED for M2.
- [2026-07-24] Staleness hashing normalizes source before hashing (`re.sub(r"\s+", " ", source).strip()`, then sha256) rather than hashing raw source. Reason: resolves the open question named in CONTEXT.md Risks — a purely cosmetic/whitespace edit (reformatting, reindent) does not invalidate a cell's recorded output, and false-positive staleness flags would erode trust in the gap-box mechanism the same way an autonomous mis-classification would. Tradeoff accepted: a semantically-meaningful edit that happens to only touch whitespace (rare) would be missed — acceptable, matches PLAN.md's "simplest approach that passes acceptance." SETTLED for M3.
- [2026-07-24] Cache is keyed by cell `id` (from nbformat, stable across edits to the same cell) and stores one hash per id, fully rewritten on every `annotate_staleness` call. A cell id with no prior cache entry is treated as not-stale (first-sight baseline) rather than stale-by-default. Reason: matches PLAN.md's acceptance test ("first run creates the cache with zero stale cells") and means a newly-added cell never spuriously flags as stale. SETTLED for M3.
- [2026-07-24] M4 built directly on top of uncommitted M3, per explicit user instruction ("start module 4") rather than waiting for a human commit first. Reason: repeats the same pattern already used for M2 on uncommitted M1 last session — read as the user's actual working cadence (build several modules, review/commit in one batch) rather than a one-off exception. Flagged in the report packet each time rather than silently treated as the new default; still never proceeds past an explicit "start module N" instruction on my own initiative. SETTLED as observed pattern, not changed as a rule in CLAUDE.md.
- [2026-07-24] Stale-hash cache path for the CLI's `render` command is `Path(f"{Path(notebook_path).stem}.cache.json")` — resolved against cwd, not against the notebook's own directory. Reason: the M2 acceptance test invokes `render` with an absolute path into the committed `tests/fixtures/` directory; a notebook-directory-relative cache path would write a stray `.cache.json` into that directory on every test run. Resolving against cwd instead matches where `report.html` already gets written and keeps test runs from mutating tracked directories. Tradeoff: two different notebooks sharing a stem, rendered from the same cwd, would collide on one cache file — acceptable for v1 single-notebook-at-a-time CLI usage. SETTLED for M4.
- [2026-07-24] M5's Anthropic client is an injected parameter (`classify_cells(cells, client=None)`), defaulting to `anthropic.Anthropic()` only when not supplied. Reason: the acceptance test can't hit the real API (no credits — see Gotchas) and CLAUDE.md requires the M5 acceptance test to run "against a mocked/fixed model response"; a fake object satisfying `.messages.create(**kwargs) -> object with .content` is enough to drive the real validation/retry/fallback code path with zero network dependency. SETTLED for M5.
- [2026-07-24] Classification uses Anthropic tool-forced structured output (`tool_choice` pinned to the one tool) with a hand-written JSON schema in `CLASSIFY_TOOL`, kept separate from the `CellClassification` Pydantic model rather than generating one from the other via `model_json_schema()`. Reason: PLAN.md's stack section calls for "Pydantic tool-forced structured output," and two small hand-written pieces are simpler to read and test than schema-generation machinery for a 2-field model. Every response is validated through `CellClassification.model_validate(...)` regardless of the tool schema, so the trust boundary (never branch on unvalidated model JSON) doesn't depend on the tool schema being airtight. SETTLED for M5.
- [2026-07-24] Retry-then-fallback is capped at `MAX_ATTEMPTS = 2` (one real retry) and treats five exception types as "malformed, try again": `ValidationError` (schema violation), `StopIteration` (no tool_use block in the response), `AttributeError`/`TypeError`/`KeyError` (unexpected response shape, e.g. `response.content` not iterable or missing `.input`). Reason: matches PLAN.md's acceptance wording exactly ("one retry, then the safe fallback") and CLAUDE.md's "Never branch on unvalidated model JSON" — every one of those exceptions means the response could not be trusted enough to read a field from. SETTLED for M5.
